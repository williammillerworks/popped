# posthog-analytics-integration - Design Document

> Version: 1.0.0 | Date: 2026-08-05 | Status: Approved
> Level: Dynamic | Plan: docs/01-plan/features/posthog-analytics-integration.plan.md

---

## 1. Overview

### 1.1 Purpose

Use the existing analytics abstraction as the sole product-event source and initialize a privacy-conscious PostHog browser client before React hydration.

### 1.2 Design Goals

- Preserve the existing typed event names and payloads.
- Keep analytics optional and non-blocking.
- Avoid automatic event duplication and admin PII.
- Limit session replay to public gameplay with explicit input masking.
- Keep the integration small enough to verify from a Preview deployment.

## 2. Architecture

### 2.1 System Architecture

```text
Gameplay components
    -> trackAnalyticsEvent(name, payload)
        -> sanitize primitive properties
            -> posthog-js capture
                -> PostHog US ingestion
                    -> Activity / insights / replay
```

The Next.js root `instrumentation-client.ts` initializes the `posthog-js` singleton before React hydration. No provider component or server SDK is required for the initial product analytics scope.

### 2.2 Component Design

| Component | Responsibility |
|-----------|----------------|
| `instrumentation-client.ts` | Validate optional public config and initialize PostHog inside a failure boundary. |
| `lib/analytics.ts` | Preserve the typed event contract, sanitize payload values, and capture without throwing. |
| `PageViewTracker` | Emit the single canonical `page_viewed` event with puzzle availability. |
| Gameplay/result components | Emit the existing domain events without raw answer text. |

Generated admin identity components, the server PostHog client, and admin CRUD captures are removed. Admin usage is operational behavior rather than public product behavior, and the current identity source is an email address rather than an immutable ID.

### 2.3 Initialization Configuration

PostHog initialization uses these explicit controls:

```ts
{
  api_host: host,
  defaults: "2026-05-30",
  autocapture: false,
  capture_pageview: false,
  capture_pageleave: false,
  capture_exceptions: !window.location.pathname.startsWith("/admin"),
  disable_session_recording: window.location.pathname.startsWith("/admin"),
  person_profiles: "identified_only",
  respect_dnt: true,
  session_recording: {
    maskAllInputs: true,
  },
}
```

Development debug logging remains available only when valid configuration exists. Missing configuration logs a development warning once and otherwise disables analytics without throwing.

### 2.4 Data Flow

1. A public interaction calls `trackAnalyticsEvent`.
2. The adapter drops `undefined` properties and permits only boolean, number, string, or `null` values.
3. The initialized singleton queues the event for US Cloud ingestion.
4. SDK/network failures are swallowed at the analytics boundary and never alter game state.
5. PostHog insights consume the existing event names; no duplicate `$pageview` or `$autocapture` events are generated by this app configuration.

## 3. Data Model

### 3.1 Event Contract

The canonical events remain:

- `page_viewed`
- `game_started`
- `guess_submitted`
- `guess_correct`
- `repeat_used`
- `next_clue_clicked`
- `answer_revealed`
- `stage_played`
- `reveal_preview_played`
- `spoiler_shown`
- `spoiler_hidden`
- `result_shared`
- `audio_error`

Properties are limited to operational dimensions such as `puzzleNumber`, `stage`, counts, mode, reason, status, and share method. Raw guesses, canonical answers, credentials, URLs with secrets, and admin emails are excluded.

### 3.2 Relationships

Anonymous PostHog distinct IDs group events into browser sessions. `puzzleNumber` relates funnel events for a daily puzzle. No Supabase row or authenticated account identity is joined in this phase.

## 4. API Specification

### 4.1 External API

- Destination: `NEXT_PUBLIC_POSTHOG_HOST`
- Project selection: `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`
- Client: `posthog-js`

### 4.2 Internal API

```ts
trackAnalyticsEvent(
  name: AnalyticsEventName,
  payload?: Record<string, boolean | number | string | null | undefined>,
): void
```

The function is client-only, synchronous to callers, and must not throw.

## 5. Implementation Plan

### 5.1 File Changes

| Path | Change |
|------|--------|
| `instrumentation-client.ts` | Add explicit capture/privacy controls and non-throwing initialization. |
| `lib/analytics.ts` | Retain PostHog capture through the existing event adapter. |
| `components/analytics/PageViewTracker.tsx` | Remove generated admin identity/sign-out concerns. |
| Admin pages/actions | Restore pre-analytics behavior. |
| `lib/posthog-server.ts` | Delete generated server client. |
| `package.json`, lockfile | Remove unused `posthog-node`; retain `posthog-js`. |
| `.env.example` | Document the exact US host and project-token placeholder. |

### 5.2 Implementation Order

1. Remove out-of-scope admin/server analytics.
2. Harden browser initialization and environment handling.
3. Install the resulting dependency tree.
4. Run lint, tests, and production build.
5. Commit and push the PR branch.
6. Wait for the automatic Vercel Preview deployment.
7. Exercise gameplay and confirm ingestion before merge.

## 6. Test Plan

### 6.1 Static and Automated Checks

- ESLint passes.
- Existing Node test suite passes.
- Next.js production build passes with and without local PostHog configuration.
- Dependency manifest contains `posthog-js` and not `posthog-node`.
- Search confirms no `posthog.identify`, admin capture event, or server PostHog client remains.

### 6.2 Preview Integration Tests

- Preview root returns successfully.
- Browser console has no PostHog initialization or hydration error.
- Network requests reach the configured US ingestion host.
- `page_viewed`, `game_started`, and a gameplay action appear in PostHog Activity.
- Admin navigation does not start a session recording.

## 7. Security and Privacy Considerations

- The public project token is intentionally browser-visible and is not an administrative API credential.
- Personal API keys, Supabase service-role keys, admin passwords, and database passwords are never sent to PostHog.
- Autocapture is disabled so DOM text and attributes are not emitted as interaction events.
- Session replay masks all inputs and is disabled on admin entry paths.
- Admin email identification and server-side admin events are excluded.
- Supabase warehouse sync is explicitly deferred; a future integration must use a dedicated read-only database role and selected columns.
- A separate privacy/consent review is required before expanding tracking scope or targeted geographies.
